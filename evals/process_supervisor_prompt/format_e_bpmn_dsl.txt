PROCESS coffee_shop_order  (BPMN-only view)

LANES
  L1 = Order Agent
  L2 = Inventory Agent
  L3 = Barista Agent
  L4 = Customer Service Agent

ACTIVITIES                                LANE
  A01  Identify Customer Request          L1
  A02  Create Order                       L1
  A03  Check Stock                        L2
  A04  Place Food on Tray                 L2
  A05  Brew Coffee                        L3
  A06  Purchase Order                     L1
  A07  Handout Order                      L1   *END*
  A08  Investigate into Customer Complaint L4
  A09  Offer Refund                       L4   *END*
  A10  Reject Complaint                   L4   *END*

GATEWAYS
  G1  XOR        after A01      branches: order | complaint
  G2  AND-split  after A03      branches: A04, A05, A06   (concurrent)
  G3  AND-join   before A07     joins: A04, A05, A06
  G4  XOR        after A08      branches: valid_claim | default(reject)

FLOW
  Start  -->  A01
  A01    -->  G1
  G1 [order]      -->  A02
  G1 [complaint]  -->  A08
  A02    -->  A03
  A03    -->  G2
  G2     -->  A04
  G2     -->  A05
  G2     -->  A06
  A04    -->  G3
  A05    -->  G3
  A06    -->  G3
  G3     -->  A07
  A07    -->  End-success
  A08    -->  G4
  G4 [valid_claim] -->  A09
  G4 [default]     -->  A10
  A09    -->  End-refund
  A10    -->  End-reject

CROSS-LANE HANDOFFS
  A transfer-control event from one lane's agent to another lane's agent
  corresponds to a BPMN sequence-flow edge that crosses the lane boundary.
  Such a transfer terminates the most recent open activity in the source
  lane with reason `via_handoff_to_<target_lane_agent>`.
  A transfer is itself NOT an activity.
